## 1. 這是什麼

`ryantsai/KKTerm` — 446 star / 55 fork / 3,308 commit，TypeScript + Rust（Tauri v2），MIT + Commons Clause。

定位是「vibe coder 與系統管理員的桌面工作站」：本機終端、SSH/SFTP/FTP/Telnet/serial、RDP/VNC、內嵌網頁、檔案瀏覽全部收斂成**單一 `Connection` 抽象**，可在同一個 tab 裡混排多窗格。加上 dashboard、IT Ops 批次任務、Windows 安裝助手、內建 AI 助理。Local-first、無 telemetry、無雲同步。

**它跟 bridge 的真正交集不是終端機，是「一個宿主 app 怎麼接多家 AI agent、怎麼管它們的動作權限」**——而它在這一層的做法跟 bridge 高度同構，∴ 值得逐項比。

## 2. 四條有實質內容的交集軸（附原文）

### 2.1 它也是 ACP client，而且有 bridge 沒有的退化路徑

> "KKTerm first tries an Agent Client Protocol (ACP) stdio backend — registry adapters for **Codex and Claude Agent**, or the native `agent acp` / `cursor-agent acp` server for **Cursor**."
>
> "If the ACP adapter is not available or fails to initialize, KKTerm falls back to the documented **one-shot vendor CLI commands** (`codex exec`, `claude -p`, or Cursor `--print --mode=ask` with a stdin prompt) … The fallback is **strictly a setup-failure path**."

bridge 的 `src/acp-providers.ts:128-130` 是 kiro / claude / codex 三個，**沒有 Cursor，也沒有「adapter 起不來就退成 one-shot CLI」這條路**。

### 2.2 危險工具核可：便宜到不像話的形狀

KKTerm 對外開了一支 `kkterm-cli` stdio **MCP server**，把 app 能力給外部 agent 用（Claude Desktop / Code / Codex / Copilot）。核可只有兩個開關：

> 危險工具位於 `*.dangerous.*` 命名空間。"when `built_in_mcp_allow_all_dangerous` is `false`, the bridge returns a `permissionRequired` tool error for any dangerous call."

也就是說：**危險性直接編在工具名字裡**，加新工具時「這是不是危險動作」變成命名當下就得決定的事，一個 boolean 管全部，不需要 per-tool 設定。

這一條為什麼重要——[[cloudflare-os]] §6 把「側效動作核可閘門」（B3）判成**不建議、YAGNI**，理由寫的是「**要新增狀態機 + UI + 儲存，成本高**」。KKTerm 這個版本沒有狀態機、沒有 UI、沒有儲存。**被推翻的是成本前提，不是價值判斷。**

### 2.3 AI context 是「投影」不是「傾倒」，而且用測試釘住

> "AI Assistant context is also a command-boundary concern. Any frontend page context, backend tool output, or debug-only assistant payload must be designed as a **compact projection, not a raw dump** of local app state."
>
> 每次請求送的被動 context 只含 "labels, ids, summaries, counts, small metadata, and current UI state"；原始碼、終端內容、截圖只能經**明確使用者動作或受限讀取工具**帶上去。
>
> "New assistant surfaces require test coverage ensuring **serialized prompts contain no raw secrets** or avoidable bulky data."

最後那句是機械層：**每開一個新的 assistant surface，就要有一支斷言「序列化後的 prompt 裡沒有 secret」的測試**。bridge 有 acp-trace 洩漏前科（[[bridge-secrets-backup]]），修的是那一次的洞；`scripts/` 裡有 `check-acp-trace-orphan.mjs`（管孤兒 trace 檔）與 `check-streaming-token-strip.mjs`（管出站 token），但**未見「新 surface 一律要有 prompt-secret 斷言」的通則型閘門**。

### 2.4 assistant-skills 就是 Anthropic SKILL.md 格式

12 支領域排障 skill（ssh / dns-dhcp / firewall-port / tls-certificate / network-connectivity / sftp / rdp / terminal-command-planner / 4 支 dashboard 相關），frontmatter 只有 `name` + `description`，跟你的正本格式一致。

我讀了 `ssh-troubleshooter/SKILL.md` 全文，值得注意的是它結尾有一段 **「KKTerm Boundaries」詞彙釘樁**：

> - Stored resources are **Connections, not profiles**.
> - Live terminal state is a **Session**.
> - Secrets belong in the OS keychain, **not chat or SQLite**.

以及工作流裡的一條紀律：「Explain likely causes **in order of evidence, not in order of convenience**」、「Do not ask the user to paste secrets into chat」。

### ⚠️ K1 必須換算方向，不能照搬

這正是 `ms-external-repo-absorption` 常見錯誤 #2 的形狀。KKTerm 是**桌面 app、使用者就坐在螢幕前**，∴ 回一個 `permissionRequired` error 讓呼叫端重試是合理的——人會看到、會去按核可。

bridge 不是：agent 常在**排程輪次、背景通知輪次、specialist 派工**裡跑，沒人在看。同一個做法搬過來，「回錯誤讓 agent 重試」會變成**靜默卡死**，代價方向剛好相反。

換算後的正確落點是：**危險動作不回錯誤，而是改走既有的 `ask` 佇列**（queue 後 turn 結束才 commit，[[cloudflare-os]] §4.1 已釐清這條語意）。要抄的是「危險性編進命名 + 單一開關 + default-deny」這三件事，不是它的錯誤回傳形狀。
