---

### 🤖 Assistant (下午5:32:47)

查了本機實際證據（Claude Code 2.1.220 binary 裡的 advisor 系統提示與 gating 邏輯、SDK 型別、你的 `~/.claude/settings.json`），以下都是從那裡讀出來的，不是憑印象。

## 一句話

**advisor = Claude Code 內建的「請一個更強的模型幫你看一眼現在這場對話」按鈕**，由 agent 自己在覺得該問的時候按。

## 它跟你想的「開個 subagent」很不一樣

官方塞給 agent 的原文（我從 binary 撈出來的）第一句就是：

> You have access to an `advisor` tool backed by a stronger reviewer model. **It takes NO parameters** — when you call `advisor()`, your entire conversation history is automatically forwarded. They see the task, every tool call you've made, every result you've seen.

三個關鍵：

| 特性 | 白話 |
|---|---|
| **零參數** | 不用寫 prompt、不用打包 context。呼叫就是 `advisor()`，沒了 |
| **整段對話自動轉發** | 顧問看得到你這場對話的全部：任務、每一次 tool call、每一筆結果。所以它不會給罐頭答案 |
| **server-side tool** | 在 Anthropic 伺服器端執行（回傳的是 `advisor_tool_result` block，tool id 前綴 `srvtoolu_`，跟 web_search 同一家族）。本機不跑任何東西、不會跳權限確認 |

對比一下你熟的東西：`PARALLEL_DELEGATE` / Task subagent 是「我要自己想清楚要問什麼、把背景打包給它」；advisor 是「它自己去讀我的完整逐字稿」。這就是為什麼 2026-07-14 那次實測，顧問的回覆能引用只出現在那場 session 裡的一次性 marker、working directory、git branch——它真的讀到了 transcript。

## 什麼時候會被呼叫

官方提示裡明寫的觸發時機：

- **開工前**（寫檔、下判斷、押注某個解讀之前）。找檔案、抓資料這種「摸清楚環境」不算開工，可以先做完再問
- **覺得做完時**——但**先把產出落地**（檔案寫好、commit 完）再叫，因為顧問要跑一段時間，session 中斷的話已落地的東西還在
- **卡住時**（錯誤反覆、方向不收斂）
- **想換做法時**

還有一條處理衝突的規矩挺有意思：如果你手上的資料指向 A、顧問說 B，**不准安靜地改成 B**，要再叫一次 advisor 講明「我查到 X，你說 Y，哪個約束決定勝負？」

## 舉個例

假設在改 bridge 的 draft streaming：

1. 你說「draft 靜默期會整段重播，修一下」
2. Agent 先 grep + read 幾個檔（摸清楚，不算開工）
3. 動手改之前 → `advisor()`。顧問看到的是「這場對話從頭到尾」：包含 agent 讀到的那段 keepalive 程式碼、它 grep 的結果、它心裡打算把間隔從 20s 改 4s
4. 顧問回：「你看到的重播現象跟 keepalive 間隔可能沒有因果關係，transcript 裡第 3 次 read 的那段 render 字串含 live 計時器——下游『內容沒變就早退』的判斷會永久失效，先確認這條」
5. Agent 沒改 keepalive，先去驗那條——這就是 advisor 的價值：**它是唯一一個看過全部證據、但沒有背負你那條推論慣性的角色**

單開一個 subagent 做這件事？你得先自己意識到「我可能推錯了」才會去打包 context——但你正因為推錯所以意識不到。advisor 繞過了這個死結。

## 你這台機器的現況

- `~/.claude/settings.json` 裡 `"advisorModel": "fable"` → 顧問是 Fable 5
- 開關方式三種：互動式 `/advisor`、CLI `--advisor <model>`、直接寫 settings。關掉是 `CLAUDE_CODE_DISABLE_ADVISOR_TOOL`
- **能力等級規則**：顧問必須「至少跟主模型一樣強」。模型 catalog 裡每個 model 有 `advisor_rank`（Haiku 4.5=1、Sonnet 4.6=2、Sonnet 5 / Opus 4.6=3、Opus 4.7/4.8/Opus 5=4、Fable 5=5），要求 `主模型 rank ≤ 顧問 rank`。這場 session 主模型是 Opus 5（rank 4）、顧問 Fable 5（rank 5）→ 合法。反過來想拿 Sonnet 當 Opus 的顧問就會被靜默跳過
- 只有第一方帳號（Claude 訂閱/API）能用，Bedrock / Vertex 不行
- **要花錢**：顧問呼叫算獨立的 model usage（有 `cost_usd_micros` 統計），按顧問模型的費率計。它有 `max_uses_exceeded` 之類的錯誤碼，代表每輪有次數上限

## 跟 bridge 的關係

`claude-agent-acp` backend 也吃得到——因為它帶 `settingSources: ["user","project","local"]`，讀的是同一份 `~/.claude/settings.json`，所以 `/advisor` 寫的設定對 ACP session 一樣生效（`scripts/check-advisor-tool.mjs` 實測過，有看到真的 `srvtoolu_` tool_call）。

但 **Kiro CLI 和 Codex 沒有這個工具**——advisor 是 Claude Code / Claude Agent SDK 專屬，跟 ACP 協定無關。所以你 `/agent kiro` 之後就沒這功能了。

## 最硬的一條：advisor 讀不到你沒讀過的東西

advisor 的輸入定義寫死在它的系統提示裡：

> They see the task, every tool call you've made, every result you've seen.

也就是說它的視野**等於我的視野**。它不會自己去 grep、不會自己去開檔（server-side 單次呼叫，沒有 agentic loop——這條我標成強推論，binary 裡沒看到它能發起 tool call 的跡象）。

對照你的覆核紀律第 2 條：「**明確要它讀原始碼，不要信 commit message / 註解 / AI.md 的自我描述**」——advisor 結構上做不到，因為它手上只有我的敘事 + 我碰過的碼。

實證直接命中這點：
- **2026-07-29**：覆核抓到 5 個孤兒 import + 1 個死碼函式。那些正是我沒 grep 到的位置，`tsc` 也看不到（`noUnusedLocals` 沒開）。advisor 同樣看不到——我沒讀過的檔案不在逐字稿裡。
- **2026-07-31**：最有價值的一條是「commit message / 註解 / AI.md 三處共用同一個錯誤因果敘事」。advisor 吃的正是**生出那個敘事的那場對話**。它可能看得到原始 tool 輸出而察覺矛盾，但它是被我的解讀先框過一輪的讀者。

## 其他四條差異

| | advisor | Fable5 push 覆核 |
|---|---|---|
| **輸入** | 我的完整逐字稿（同源輸入、異源模型） | 乾淨 context + 自己讀 diff/原始碼（雙異源） |
| **對象** | 「這場對話」 | 「這個 commit」——含跨 session、含我改了但沒討論到的部分 |
| **觸發** | **模型自己決定要不要叫**（opt-in） | R-2 hard requirement（gate） |
| **產出** | 一段建議文字 | 可逐條重現／駁回的 findings，可多輪範圍收窄 |

第三條最要命：advisor 是「agent 覺得該問的時候會問」——那正是 #007（同源自審漏看率 50–67%）失效的那個假設。你整套方法論反覆在做的事就是把承重的東西從「模型想不想」挪到 always-on hook / hard requirement。advisor 是 opt-in，天生站錯邊。

```
設計決策前 ── 卡住時 ── 實作 ── commit ── push
