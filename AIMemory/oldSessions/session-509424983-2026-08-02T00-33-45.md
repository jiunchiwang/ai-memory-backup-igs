### 🤖 Assistant (上午8:30:47)

接續上輪分析——你問的是讓 `/dream` 各步驟可以指定 model。

**現狀**：`dream.json` 只有 `steps[]` 和 `continue_on_error`，沒有 model 欄位。所有步驟共用當前 session 的 provider/model。

**關鍵限制**：mid-dream 切 model 需要 `switchProvider()`，這會 **drop 當前 session 再 create 新的**——步驟之間的 context 會斷掉。

---

## 可行方案

| 方案 | 說明 | 複雜度 |
|------|------|--------|
| **A. 全域 dream model** | `dream.json` 加 `"model": "gemini"`，dream 開始時切過去、結束後切回 | 低 |
| **B. 指令參數** | `/dream --model deepseek` 臨時覆蓋 | 低 |
| **C. per-step model** | 每個 step 可指定 `"model": "local"`，切換時會斷 context | 高 |
| **D. per-step agent** | 每個 step 指定 agent key（`kiro`/`claude`） | 最高 |

**建議先做 A+B**（全域 + 指令參數），理由：
- 日常對話用 Opus、`/dream` 用便宜 model（Gemini/DeepSeek/local）是最常見需求
- 實作簡單，不需改 session 管理邏輯
- per-step model 的 context 斷裂問題先觀察實際需求再決定

schema 變成：
```json
{
  "model": "gemini",        // optional，預設用當前 model
  "steps": [...],
  "continue_on_error": true
}
```

指令：`/dream --model local` 參數優先於設定檔。你要我做「全域 dream model + 指令參數」還是「per-step model」？
