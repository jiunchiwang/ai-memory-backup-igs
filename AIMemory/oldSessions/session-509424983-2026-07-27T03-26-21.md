## 🧩 Spine-Animation-AI Skill 打包機制分析

### 設計理念

**「自包含 Skill」**— 使用者只需把 `SKILL.md` 貼進 Claude Projects，不需 clone repo、不需裝 dependency、Claude 自己會把 scripts 寫到磁碟再執行。

### 架構

```
SKILL.template.md     ← 人類編輯（prose + 指令 + 佔位符）
       ↓
build_skill.py        ← CI 自動跑（找佔位符、注入腳本）
       ↓
SKILL.md              ← 自動生成（完整自包含，Claude 可直接用）
```

### 關鍵機制

#### 1. 佔位符語法

```markdown
<!-- EMBED:scripts/position_parts.py -->
```

template 裡放這個 marker，build script 會找到並替換成實際內容。

#### 2. build_skill.py 核心邏輯

```python
# 正則找所有 <!-- EMBED:path --> 標記
pattern = re.compile(r"<!--\s*EMBED:\s*(.+?)\s*-->")

# 從後往前替換（保持 index 正確）
for match in reversed(matches):
    filepath = match.group(1)
    content = (repo_root / filepath).read_text()
    
    # 包成 collapsible details + code block
    replacement = (
        f"<details open>\n<summary>\n"
        f"📄 `{filepath}` ({line_count} lines)\n</summary>\n\n"
        f"```{lang}\n{content}\n```\n\n"
        f"</details>"
    )
    result = result[:match.start()] + replacement + result[match.end():]
```

#### 3. 輸出格式（`<details>` 折疊塊）

```markdown
<details open>
<summary>
📄 `scripts/position_parts.py` (231 lines)
</summary>

```python
#!/usr/bin/env python3
...actual script content...
```

</details>
```

#### 4. GitHub Actions 自動化

`.github/workflows/build-skill.yml` 在 push 時自動 rebuild，確保 SKILL.md 永遠與 scripts 同步。

### Skill 使用流程（Claude 端）

1. **Claude 讀 SKILL.md** → 看到 embedded scripts
2. **Claude 寫 scripts 到磁碟** → `mkdir -p /home/claude/spine-scripts/` → 逐一寫入
3. **Claude 跑 pipeline** → 執行 Python scripts 處理使用者上傳的圖片
4. **輸出結果** → skeleton.json + atlas + preview.html

### 與你現有 skill 體系的比較

| | 你的 skill（AI-canonical） | spine-animation-ai |
|---|---|---|
| **正本位置** | `G:\AI\AI-canonical\skills\` | GitHub repo |
| **投影機制** | `sync.ps1` junction 到各 CLI | 使用者手動貼 SKILL.md |
| **腳本管理** | 分離（skill 引用外部 scripts） | 內嵌（scripts 直接進 SKILL.md） |
| **更新同步** | 手動跑 sync | GitHub Actions 自動 rebuild |
| **可攜性** | 透過 `${MEMORY_DIR}` 等變數 | 完全自包含（零外部依賴） |

### 可借鏡的點

1. **Scripts 內嵌模式** — 適合「單一用途、需要腳本」的 skill
   - 你的 `excel-to-ai-doc`、`uk-slot-codegen` 可能適用
   - 好處：使用者不需要 clone repo、設路徑

2. **`<!-- EMBED:path -->` 佔位符** — 乾淨的 DRY 機制
   - template 保持可讀，實際內容自動注入

3. **CI 自動同步** — 避免「改了 script 忘了更新 SKILL.md」的 drift

### 不適用的場景

- **頻繁更新的腳本** — 每次改都要 rebuild，不如保持分離
- **多 skill 共用腳本** — 內嵌會重複
- **需要環境變數的腳本** — 內嵌後路徑寫死（你的 `${MEMORY_DIR}` 模式更靈活）

## 🔬 Spine-Animation-AI 可借鏡設計研究報告

### 值得借鏡（按優先級）

#### 1. 📦 自包含 Skill 打包機制
**原理：**
- `SKILL.template.md` 放人類可讀的指令 + `<!-- EMBED:scripts/xxx.py -->` 佔位符
- `build_skill.py` 用正則找佔位符，把腳本包成 `<details>` 折疊塊注入
- GitHub Actions 在 `scripts/` 或 template 改動時自動 rebuild
- 輸出的 `SKILL.md` 完全自包含，貼進 Claude Projects 即可用

**借鏡方式：**
- 為 AI-canonical 建立 `build_skill.py`，讓需要腳本的 skill（如 `excel-to-ai-doc`、`uk-slot-codegen`）可以選擇「內嵌模式」
- 新增 `SKILL.template.md` + `SKILL.md` 雙檔結構，template 是 source of truth

**預估工作量：** 0.5 天（build script + CI workflow）

**適用場景：** 單一用途、獨立腳本、不常更新的 skill

---

#### 2. 📋 YAML Frontmatter 觸發詞設計
**原理：**
```yaml
---
name: spine-animation
description: >
  Create Spine 2D skeletal animations...
  Also trigger when the user mentions "Spine animation", "2D rigging", 
  "skeletal animation", "bone animation", "cutout animation"...
---
```
把觸發條件（trigger keywords）直接寫在 description 裡，Claude Projects 會用這個來決定何時啟用 skill。

**借鏡方式：**
- bridge 的 skill routing 已用 embedding 比對 description
- 可在 SKILL.md 加入「Also trigger when...」段落，提供更明確的觸發詞供 embedding 抓取
- 或建立 `triggers:` 欄位標準化這個資訊

**預估工作量：** 0.25 天（更新 skill-creator template）

---

#### 3. 🔧 Debug 輸出設計（`--debug` flag）
**原理：**
```bash
python position_parts.py --debug debug/
# 產出：
# - debug/comparison.png （左右對比：reference vs composite）
# - debug/bboxes.png （各部位邊界框 + 標註）
# - debug/fg_mask.png （前景遮罩）
# - debug/sift_<part>.jpg （每個部位的 SIFT match 可視化）
```
每個步驟都可選擇性輸出中間產物供人類檢查。

**借鏡方式：**
- `uk-slot-codegen` 可加類似的 `--debug` 模式，輸出 anchor match 視覺化
- specialist 的 `artifacts/` 可加結構化 debug 產物（不只是 JSON log）

**預估工作量：** 依 skill 而定（codegen ~1 天）

---

#### 4. 📝 調整格式標準化（adjustment-format.md）
**原理：**
```json
{
  "adjustments": {
    "right-arm": {
      "original_offset": { "x": -1.5, "y": 0 },
      "user_offset": { "dx": -29.4, "dy": -84.1, "drot": 0 },
      "final_offset": { "x": -30.9, "y": -84.1 }
    }
  }
}
```
**所有調整都保留原值 + delta + 最終值**，可 review、revert、compose。

**借鏡方式：**
- factlint / wikisync 的修改建議可採用類似格式
- specialist 回報的「修改建議」可標準化成 `original → delta → final` 三元組

**預估工作量：** 0.5 天（定義 schema + 更新相關 code）

### 不適用 / 謹慎採納

#### 1. ❌ Claude 自己寫 scripts 到磁碟
**原因：**
- bridge 環境是 ACP + Telegram，不是 Claude Code 本機執行
- Kiro CLI 的 shell tool 可以跑 Python，但讓 agent 每次 session 都「寫腳本再執行」很脆弱
- 你的 `${SKILL_DIR}` 機制已經解決這問題（腳本放固定位置，skill 引用）

#### 2. ❌ `/home/claude/spine-scripts/` 硬編碼路徑
**原因：**
- 這是 Claude Code 環境的假設
- 你的 `${MEMORY_DIR}` 變數注入機制更靈活，應繼續用

#### 3. ⚠️ 整合 Gemini 做角色拆分
**原因：**
- 功能很酷（整圖 → 部位 PNG）
- 但需要 `GEMINI_API_KEY`，增加環境依賴
- UK slot 美術已經有分離的部位 PNG，不需要這功能
- **如果未來有需求**：可考慮把 `split_character.py` 獨立成一個 skill

#### 4. ⚠️ PolyForm Noncommercial 授權
**原因：**
- 公司專案（UK slot）屬商用，不能直接用 repo 裡的 code
- 可以「借鏡概念」但不能 copy-paste 實作
- SIFT+RANSAC 演算法本身是公開知識，自己實作沒問題

### 開放問題

1. **AI-canonical 要不要支援「內嵌模式」？**
   - 好處：某些 skill 可以完全自包含，不依賴本機路徑
   - 壞處：增加維護複雜度（兩種模式並存）
   - 建議：先 pilot 一個 skill（如 `excel-to-ai-doc`），看效果再決定

   - 目前 embedding router 只看 description 文字
   - 可以額外提取 `triggers:` 欄位做 keyword match 加速
   - 需要改 `embed-router.ts`
