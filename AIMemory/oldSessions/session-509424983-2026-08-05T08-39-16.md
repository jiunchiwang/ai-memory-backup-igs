## Pi.dev 研究報告

### 一句話定位
**Pi 是一個開源、極簡、高度可擴展的終端機 coding agent harness**，由 Earendil Inc. 開發，MIT 授權。

### 核心理念
> "There are many agent harnesses, but this one is yours"

Pi 的設計哲學是**讓你適配 agent，而不是被 agent 綁架**。它刻意保持核心最小化，把其他 agent 內建的功能（sub-agents、plan mode、MCP、權限彈窗）全部外推給 extension 實現。

### 主要特色

| 面向 | Pi 做法 |
|------|---------|
| **Provider 支援** | 15+ provider（Anthropic / OpenAI / Google / Azure / Bedrock / Mistral / Groq / Ollama…），mid-session `/model` 切換 |
| **四種運行模式** | Interactive TUI、Print/JSON、RPC (stdin/stdout JSONL)、SDK (Node.js embed) |
| **擴展機制** | TypeScript extensions（tool / command / keybinding / event / TUI widget） |
| **Skills** | 類似你的 SKILL.md，on-demand 載入、progressive disclosure |
| **Prompt templates** | 可重用 prompt，`/name` 展開 |
| **Themes** | 終端主題 |
| **Packages** | 把上述四種打包成 npm / git 可分享的套件 |
| **Session 結構** | Tree-structured history，可 branch、export HTML、share 到 gist |
| **Context engineering** | 最小 system prompt、AGENTS.md / SYSTEM.md 載入、compaction 可自訂 |
| **Steering** | 執行中可送 steering message（Enter）或 follow-up（Alt+Enter） |

### 它「故意不做」的事（留給 extension）
- **No MCP** — 用 CLI tool + README 或自己寫 extension
- **No sub-agents** — 用 tmux spawn 多個 Pi，或自己寫
- **No permission popups** — 跑容器，或自己寫確認流程
- **No plan mode** — 寫 file，或自己寫
- **No built-in TODO** — 用 TODO.md
- **No background bash** — 用 tmux

### 與 Bridge 的對比

| 維度 | Pi | telegram-kiro-bridge |
|------|-----|---------------------|
| 定位 | 終端 TUI agent harness | Telegram ↔ ACP agent 橋接器 |
| 前端 | 終端 TUI | Telegram Bot |
| Agent 後端 | 自帶（直接呼 API） | 靠 ACP CLI subprocess（Kiro / Claude / Codex） |
| MCP | 不內建 | 內建 memory / bridge-actions MCP |
| Session | Tree-structured JSONL | ACP session + archive |
| Skill | Markdown + CLI tools | SKILL.md + agent MCP |
| Provider 切換 | `/model` | `/model` + `/agent` |
| 可程式化 | SDK / RPC | ACP JSON-RPC |

### 值得借鏡的點

1. **Tree-structured session** — 可隨時 branch 回去，比線性 session 更靈活
2. **Extension 生態** — 打包成 npm 可分享，比我們的 skill junction 更標準化
3. **Steering vs Follow-up 區分** — 明確的「打斷」與「追加」語意
4. **Context engineering 文件化** — AGENTS.md / SYSTEM.md / compaction 機制寫得很清楚
5. **llama.cpp 整合** — `/llama` 直接管理本地模型

### 不適用於我們的部分

- 它是終端 TUI → 我們是 Telegram Bot，前端完全不同
- 它不走 ACP → 我們整個架構綁 ACP stdio
- 它的 RPC 是自定義 JSONL → 我們是 ACP JSON-RPC

---

**結論**：Pi 是同賽道（coding agent）但不同切入點的產品。它的 extension 打包機制和 tree session 值得研究，但要整合進 bridge 得大改架構，短期內更適合當參考而非直接採用。

## 一、OpenCodex（opencodex.me）— Universal Provider Proxy

### 定位
**本地 proxy，讓 Codex CLI / Claude Code / Claude Desktop / Grok Build 用任意 LLM**

### GitHub
`lidge-jun/opencodex` — 7.3k ⭐、3495 commits、574 forks

### 核心功能

```bash
npm install -g @bitkyc08/opencodex
ocx start   # proxy + dashboard on localhost:10100
```

| 功能 | 說明 |
|------|------|
| **40+ Provider** | OpenAI / Anthropic / Google / xAI / Kimi / DeepSeek / Groq / Ollama / Azure / OpenRouter… |
| **Wire format 翻譯** | 把 Codex 的 Responses API 轉成各家 API，streaming / tool calls / reasoning tokens / images 雙向轉譯 |
| **ChatGPT 帳號池** | thread affinity、quota-aware 自動切換、cooldown 處理 |
| **Combos** | 一個虛擬 model id 背後接 failover 或 weighted round-robin |
| **Sub-agent routing** | 在 Codex 的 sub-agent picker 裡放任意模型 |
| **Web dashboard** | `http://localhost:10100` 管理 provider / model / account / 即時 request log |
| **OAuth 整合** | xAI / Anthropic / Kimi 可 OAuth 登入，不用手貼 API key |
| **Web search & vision sidecar** | 非 OpenAI 模型透過 ChatGPT 登入獲得搜尋和圖片理解 |

### Model routing 語法
```bash
codex -m "anthropic/claude-opus-5" "Explain this stack trace"
codex -m "google/gemini-3-pro" "Write unit tests"
codex -m "ollama/llama3" "Refactor this"
```

### CLI 指令
```bash
ocx init          # 互動式設定
ocx start         # 前景跑 proxy
ocx service       # 背景 daemon
ocx codex-shim    # 按需啟動（不常駐）
ocx provider ...  # 管理 provider
ocx account ...   # 管理 ChatGPT 帳號池
ocx combo ...     # 管理 failover/round-robin
ocx stop          # 停止並還原 Codex 原始設定
```

### 支援平台
| OS | Service Manager |
|----|-----------------|
| macOS (arm64/x64) | launchd |
| Linux (x64/arm64) | systemd (user unit) |
| Windows (x64) | Task Scheduler / WinSW |

### ⚠️ 風險警告
> **Anthropic（Claude）可能會暫停或限制透過第三方 proxy 路由 API 流量的帳號。** 使用前先讀各家 ToS。
