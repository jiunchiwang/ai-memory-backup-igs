## Cloudflare OS 研究筆記

**一句話**：Cloudflare 內部用了很久的「AI 生產力作業系統」，2026-08 開源（Apache-2.0），跑在 Workers 上。賣點不是 chat UI，是**「agent 讀過什麼」被記錄下來當成權限依據**。

### 三個核心概念

| 概念 | 是什麼 |
|------|--------|
| **Gadget** | 每個使用者自己的 app 實例（不是集中式 SaaS）。AI 幫你寫、幫你改，跑在 sandbox。範本叫 **blueprint** |
| **Gatekeeper** | 每個外部服務一支 Worker，負責 OAuth／憑證／政策／稽核。agent 拿到的是**typed binding 不是原始憑證**：`await env.PROJECT.listIssues({teamId:"ENG", state:"open"})` |
| **Observer** | 記錄「這個 Gadget 讀過哪些資源」，分享時反過來驗收件人**自己是否也有那些資源的權限** |

OS 類比（README 自己講的）：Durable Objects＝kernel、Gatekeeper＝device driver、Dynamic Worker＝process、blueprint＝執行檔。

### 兩個我覺得真的新的設計

**1. observation 當權限依據（`docs/observers.md`）**
Gadget 每次透過 Gatekeeper 讀資料就記一筆 observation。非擁有者要開這個 Gadget 時，系統逐一問各 Gatekeeper `addObserver()`：「這個人能不能存取目前為止讀過的全部東西？」全過才寫 `ObserverRecord`。往後若某筆 observation 標了 `excludeObservers`，那次讀取就被擋掉。分享權限一收回，記錄刪除並呼叫 `removeObserver()`。
→ 這解的是「我把 AI 產出分享給你，結果它裡面混了你本來看不到的資料」。

**2. Gatekeeper 的非同步人工核可**
需要人簽核的動作，**在本地模擬結果**讓 agent 先繼續做，真動作排隊等審。跟我們現在 ASK 是同步阻塞剛好相反。

**3. lazy revocation（`docs/sharing.md`）**
權限是一張從 owner 出發的可達圖，`open()` 時才即時算 effective role，不存快取。撤銷只砍邊、不做級聯刪除——「失去唯一路徑的人只是變成不可達，在 `open()` 被拒，而不是從儲存中被清掉」∴ 撤銷可逆。share link 只存 HMAC-SHA-256。

### 對 bridge 的初步差距判定

| 面向 | Cloudflare OS | bridge 現況 | 判定 |
|------|--------------|------------|------|
| 動作走 mediated capability 而非裸憑證/裸 token | Gatekeeper typed binding | bridge-actions MCP tool（policy 已明訂裸 token 只是 fallback） | **已有**（同一個 move） |
| 團隊 context / skill 策展 | `.agents/skills/` | AI-canonical 正本 + wiki | **已有** |
| Observer／permission graph／share link | 完整一套 | — | **不需要**——那整套是為了擋**員工之間**的洩漏，bridge 是單人 |
| 非同步人工核可（先模擬、後審） | 有 | ASK 是同步阻塞 | **值得借鏡**（唯一結構性差異） |
| observation 當 provenance | 存取控制用途 | 記憶系統有證據分級但無「讀過什麼」的機械記錄 | **可評估**（稽核角度，不是權限角度） |

### 該知道的限制

- **early access**，README 自承「非常能用，但還有很多粗糙邊角」，且是 v2 完全重寫
- **「我們目前不接受外部貢獻」** —— 小 PR 可以，實質貢獻會被關。∴ 若真要吸收，回饋 bug 給上游這條路是不通的
- 本機試跑：`pnpm run-local` → http://localhost:8787
